# Сборка работы и ориентация страниц

Добавлено 30.09.2026. Это отдельная локальная команда; кнопки сборки в веб-интерфейсе пока нет.
Основное приложение до этого не объединяло PDF: оно выбирало один основной файл.

## Установка

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-pdf.txt
brew install poppler
```

Используйте `.venv/bin/python` для команд ниже. В Linux вместо Homebrew установите
пакет `poppler-utils`. Для основного веб-приложения эти зависимости не обязательны.

## Подготовка

Сначала установите принадлежность **всех** частей одному студенту и одному ДЗ.
Передайте PDF/JPG/PNG в явном порядке, без общего glob по папке группы:

```bash
.venv/bin/python scripts/assemble_submission.py prepare \
  --directory data/bundles/student-hw01-preview \
  '/absolute/path/part1.pdf' '/absolute/path/part2.pdf' '/absolute/path/page.jpg'
```

Получатся `preview.pdf`, изображения всех страниц в `preview-pages/` и `manifest.json`.
Порядок файлов соответствует аргументам команды, внутри PDF сохраняется исходный порядок.
Номер `1` в manifest означает первую страницу исходника.

Агент или преподаватель открывает **каждую** картинку, проверяет направление текста,
полноту и порядок. В manifest для каждой страницы задаёт:

```json
{"source":"/absolute/path/part1.pdf","page":1,"rotate_clockwise":90,"orientation_checked":true}
```

Поворот дополнительный относительно preview, по часовой стрелке: 0/90/180/270.
Для текста, лежащего на боку, выберите нужные 90 или 270; для перевёрнутого — 180.
Порядок элементов `pages` определяет порядок итоговых страниц. Исключение и дублирование
страниц блокируются: каждая входная страница должна попасть в результат ровно один раз.
Если нужен отбор только части исходника, сначала подготовьте отдельную производную копию
и зафиксируйте причину; не удаляйте страницу из manifest незаметно.

## Сборка и проверка

```bash
.venv/bin/python scripts/assemble_submission.py build \
  data/bundles/student-hw01-preview/manifest.json \
  --directory data/bundles/student-hw01-final
```

Результат: `submission.pdf`, `page-map.json` с исходными путями, SHA-256 и поворотами,
а также итоговые изображения `pages/`. Агент повторно открывает итоговые страницы.
`final_visual_check_required: true` напоминает об этом; скрипт не умеет доказать,
что человек/агент действительно посмотрел картинку.

После визуальной сверки PDF можно импортировать под именем с ФИО; manifest и карту
страниц хранить рядом. Автоматическая регистрация составной работы в БД пока не реализована.
Исходные файлы и существующие каталоги результатов не перезаписываются. При ошибке рендера
может остаться незавершённый каталог; используйте новый каталог для повторной попытки.

## Что именно исправляется

- У фотографии учитывается EXIF Orientation, включая зеркальные преобразования.
- У PDF сохраняется существующий `/Rotate`, затем добавляется выбранный поворот.
- PDF-страницы не превращаются в картинки при объединении: сохраняется текстовый слой.
- Фотографии конвертируются в PDF; возможна перекодировка изображения, оригинал сохранён.
- Хеш каждого исходника сверяется перед сборкой; нельзя незаметно заменить файл между этапами.
- Альбомный лист не считается ошибкой: ориентация определяется направлением текста.

Автоматический OCR-поворот рукописи пока не применяется. Надёжный рабочий вариант сейчас:
агент самостоятельно осматривает preview и задаёт повороты; преподавателю передаются лишь
неоднозначные случаи. OCR/OSD можно добавить позднее как подсказку, а не окончательное решение.

Реализация использует [поворот страниц pypdf](https://pypdf.readthedocs.io/en/stable/user/cropping-and-transforming.html)
и [EXIF transpose Pillow](https://pillow.readthedocs.io/en/stable/reference/ImageOps.html).
