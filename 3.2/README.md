# Задание 3.2. Следующий клик

GRU + CatBoost. **Лучший Public Accuracy — 0,41172.**

По истории действий клиента я предсказывал, какой из 32 банковских продуктов он откроет следующим. Лучшей стала отправка `submission_gru_stack_v2.csv`; её копия лежит в `results/submission_v2.csv`.

## Запуск

Нужны Python 3.12 и uv. В папку `3.2/data` положите `test.parquet`, `event_dictionary.parquet` и `sample_submission.csv` из соревнования.

Из корня репозитория:

```bash
cd 3.2
uv sync --frozen
uv run --frozen python predict.py --verify-reference
```

Скрипт загрузит сохранённые модели, посчитает признаки и сравнит прогноз с лучшей отправкой. Результат сохранится в `outputs/submission.csv`. То же самое можно запустить из `solution.ipynb`.

## Что я пробовал

Сначала я сделал TF-IDF + Logistic Regression: превратил коды действий и продуктов в текст. Этот вариант дал **0,32623** на Kaggle и стал отправной точкой.

Потом я попробовал Item2Vec, чтобы получить векторы продуктов по их появлениям в одной сессии. Вместе с CatBoost результат вырос до **0,35462**.

После этого я больше занялся признаками. Добавил счётчики просмотров и кликов, давность действий, последние события, переходы между продуктами и связи между действиями и продуктами. Этот CatBoost я назвал v7. Он получил **0,39197**.

Дальше я попробовал GRU, чтобы учитывать порядок действий. Взял шесть слоёв ширины 384 и последние 128 событий — получилось около 6,1 млн параметров. Кроме кодов действий и продуктов, сеть получает час, день недели, паузы между событиями и границы сессий. Для каждого продукта она отдельно учитывает подходящие события из истории.

Лучше всего сработал вариант, где ещё один CatBoost объединяет оценки GRU, прогнозы v7 и статистики клиента по продукту. У этого последнего CatBoost 33 дерева глубины 4. Так я получил **0,41172**.

Я также пробовал дольше обучать сеть и менять параметры. Несколько раз получал небольшой локальный плюс, который не переносился на Kaggle. Поэтому основным оставил v2.

В последнем варианте я добавил признаки недавнего интереса и поправки оценок по отдельным продуктам. На контрольном окне точность выросла с **42,48% до 43,38%**, но отправить этот вариант уже не смог: закончились попытки.

Локальные результаты и разбиения я сохранил в `results/experiments.csv`. У ранних экспериментов разбиения отличаются, поэтому их локальные оценки напрямую не сравниваю.

## Как я проверял

Для GRU я разделил клиентов по времени: 70 тысяч на обучение сети, 10 тысяч на обучение следующего CatBoost, по 5 тысяч на раннюю остановку и подбор настроек, последние 10 тысяч — на проверку. Прогнозы v7 для следующего CatBoost получал на клиентах, которых соответствующая модель v7 не видела при обучении и настройке.

Для GRU я добавил примеры из прошлых целевых кликов. Перед каждым таким кликом обрезал историю и убирал ещё пять предыдущих событий. В финальном обучении GRU продолжала учиться на первых 90 тысячах клиентов, а следующий CatBoost обучался на оставшихся 10 тысячах. В GRU получилось четыре локальные эпохи и две эпохи продолжения. Seed — 42.

Последнее контрольное окно я использовал несколько раз. По результатам отправок увидел, что одного улучшения на нём недостаточно, чтобы ожидать такой же прирост на Kaggle.

Перед сдачей я проверил получение прогноза из сохранённых весов в чистой копии проекта. Совпали все **12 359 ответов**, и сам CSV совпал побайтно. Полное обучение при этой проверке заново не запускал. Отчёт лежит в `results/verification.json`.

## Обучение и файлы

Для обучения дополнительно нужен `data/train.parquet`:

```bash
uv run --frozen python train.py --experiment gru_stack_v2 --data-dir data --output outputs/retrained
```

Для нового запуска нужна пустая папка результатов. Другие этапы доступны через `--experiment`: `tfidf`, `item2vec`, `catboost_v7`, `calibration_v6`.

- `solution.ipynb`, `predict.py` и `train.py` — запуск прогноза и обучения.
- `src/`, `gru_click/` и `experiments/` — признаки, модели и обучение.
- `configs/` — настройки пяти экспериментов; `models/` — сохранённые финальные веса.
- `results/` — лучший CSV, метрики и отчёты проверок.
